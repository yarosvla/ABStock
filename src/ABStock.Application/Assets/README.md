# Каталог активов

`IAssetCatalog` хранит сведения об активах независимо от выбранной страницы UI и запусков торгов.
Метод `AddABStockApplication()` регистрирует каталог как singleton: разные DI-скоупы используют один общий экземпляр.

```csharp
var asset = catalog.Create(new CreateAssetRequest(profile, 100m));
var sameAsset = catalog.Get(asset.AssetId);
var allAssets = catalog.GetAll();
```

- `profile`: готовый `ABStock.Shared.AssetProfile`, созданный ИИ, запасным алгоритмом или вручную. Сам каталог не обращается к ИИ.
- `Create` создаёт актив и возвращает его сведения: `AssetId`, профиль, стартовую цену и время создания.
- `AssetId` генерируется один раз при создании и не меняется при последующих чтениях. Название не является идентификатором: активы могут называться одинаково.
- `Get` получает актив по ID и возвращает `null`, если его нет. `GetAll` возвращает независимый снимок списка, доступный только для чтения.
- Профили, списки факторов и массивы эмбеддингов копируются при создании и чтении, чтобы внешний код не мог изменить данные каталога.
- Создание актива не запускает и не останавливает торги, не создаёт агентов и не заменяет другие активы.

На первом этапе используется `InMemoryAssetCatalog`: данные хранятся в памяти до завершения процесса сервера и не сохраняются после перезапуска.
Существующий UI и раннер для одного актива пока не изменены. Отдельные движки для нескольких активов в общей сессии и сохранение каталога в SQLite будут добавлены следующими этапами.
